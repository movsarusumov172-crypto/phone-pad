# PhonePad — телефон как контроллер для Forza Horizon 6 на ПК

Связка из двух частей:

* **iPhone-приложение** — экранный пад с мультитачем, гироскопом, CoreHaptics-вибрацией, звуками и HUD.
* **PC-сервер** (Windows, .NET) — принимает ввод по сети, создаёт **виртуальный контроллер Xbox 360** (XInput) через драйвер ViGEmBus, принимает телеметрию FH6 и отправляет обратно тактильные эффекты, звуки и HUD.

```
  iPhone (тач, гироскоп)  ──UDP 8888: ввод──▶  PhonePadServer ──▶ виртуальный Xbox 360 (XInput) ──▶ Forza Horizon 6
          ▲                          │
          └────UDP 8889: вибрация, звуки, HUD────┘
                                        ▲
                          UDP 5300: телеметрия FH6 (Data Out)
```

## Быстрый старт

1. **На ПК:** скачайте `PhonePadServer-win-x64` из [артефактов сборки](https://github.com/movsarusumov172-crypto/phone-pad/actions/workflows/build.yml),
   запустите `PhonePadServer.exe` (до установки драйвера ViGEmBus можно запустить
   с `--backend console`). Сервер сам напечатает IP-адрес вашего ПК.
2. **На iPhone:** возьмите неподписанный IPA из тех же артефактов и переподпишите
   его через [Sideloadly](https://sideloadly.io) вашим Apple ID.
3. **В приложении:** шестерёнка → введите IP ПК и порт `8888` → «Подключиться».
4. **В FH6:** `Settings → HUD and Gameplay → Data Out → ON`, `Data Out IP` = IP ПК,
   порт `5300` — тогда заработает вибрация по телеметрии, HUD и «световая полоса».

Без шага 4 приложение уже работает как обычный экранный геймпад.

## Что починено в этой версии

> **Важно:** исходная iOS-часть из архива **не компилировалась** — ошибки были
> неочевидные (`connection = nil` внутри `if let connection`, несуществующий
> параметр `CHHapticEvent.ParameterID.hapticFrequency`, смешение `Float` и
> `Double` в синтезе звуков). То есть приложение из архива нельзя было собрать
> даже в Xcode. Теперь оно собирается, и это проверяется в CI на каждом пуше.

**iOS-приложение**

* `updateUIView` писал состояние напрямую в `@Published`, минуя потокобезопасный снимок.
  Из-за этого фоновый цикл отправки слал **устаревшее** состояние пада — кнопки и стики «не нажимались».
  Теперь запись идёт только через `setState()`.
* Отпускание одного триггера обнуляло **оба**, а отпускание одного стика — **все четыре оси**.
  Теперь отпускается только то, что отпустили.
* Переключатель «Звуки контроллера» ни на что не влиял — звук играл всегда.
* Переключатель «Вибрация» не глушил уже идущую вибрацию.
* Потеря связи не определялась: приложение молча показывало «подключено».
  Добавлен ping/pong: телефон спрашивает сервер каждые 2 секунды и показывает ошибку, если ответа нет.
* Длительность эффектов (`durationMs`) игнорировалась — вибрация могла не прекращаться.
* Шкала оборотов считалась от фиксированных 7500 об/мин → сервер теперь присылает
  реальную красную зону двигателя (поле `maxRpm` в HUD).
* Фильтр гироскопа (`smoothing`) был объявлен, но не применялся — руль дрожал.
* При сворачивании приложения ввод не сбрасывался — в игре оставался зажатый газ.
* Настройки подключения (IP и порты) теперь запоминаются между запусками.
* Добавлена «световая полоса» (эмуляция light bar) и отображение сообщений сервера.
* `Info.plist` требовал `armv7` — на современных iPhone приложение не поставилось бы.

**PC-сервер**

* **Залипание газа:** если телефон замолчал, пад оставался в последнем состоянии навсегда.
  Добавлен watchdog (`--timeout`, по умолчанию 500 мс) — ввод сбрасывается автоматически.
* Вибрация не прекращалась после окончания эффекта и после конца гонки: сервер не слал «стоп».
* `Hello` не сбрасывал счётчик пакетов — новая сессия отбрасывалась как «старая».
* Ошибка отправки отчёта роняла весь цикл обновления пада.
* Неизвестный тип пакета считался «State».
* Настройки портов и частоты не проверялись: неверный порт ронял сокет, частота 1000 Гц съедала CPU.
* Добавлены `--help`, `--timeout`, вывод `maxRpm` в HUD, световая полоса, ответ на ping.

**Симулятор и документация**

* Симулятор учитывает объявленную длину полезной нагрузки и новый формат HUD.
* Добавлен режим `--mode selftest` (проверка кодеков без сети) и `--drop-after`
  (проверка watchdog: сервер должен сбросить пад).
* Протокол и README актуализированы под новые поля и поведение.

## 1. Подготовка ПК (Windows)

### 1.1 Драйвер ViGEmBus

Виртуальный Xbox-контроллер создаётся драйвером ViGEmBus 1.22.0 — он подписан Microsoft и работает на Windows 10/11:

1. Скачать официальный установщик: <https://github.com/nefarius/ViGEmBus/releases/tag/v1.22.0> → `ViGEmBus_1.22.0_x64_x86_arm64.exe`
2. Запустить от администратора, перезагрузить ПК.
3. Проверить: Диспетчер устройств → «Системные устройства» → `Virtual Gamepad Emulation Bus`.

> Дополнительных DLL рядом с программой **не нужно**: нативная `ViGEmClient.dll` вшита внутрь NuGet-пакета `Nefarius.ViGEm.Client` (Costura).

### 1.2 Сборка сервера

Нужен [.NET 8 SDK или новее](https://dotnet.microsoft.com/download):

```powershell
cd pc
dotnet publish src/PhonePad.Server -c Release -f net8.0 -r win-x64 --self-contained -o publish
```

Готовый exe: `pc/publish/PhonePadServer.exe` (запускать обычным образом, права админа не нужны).
Готовый exe из CI лежит в артефактах сборки (`PhonePadServer-win-x64`).

### 1.3 Запуск

```powershell
cd pc\publish
.\PhonePadServer.exe
```

Сервер сам напечатает IP-адреса вашего ПК — его нужно ввести в приложении на телефоне.

Аргументы:

| Аргумент | По умолчанию | Назначение |
|---|---|---|
| `--port N` | 8888 | порт ввода от телефона |
| `--feedback-port N` | 8889 | порт обратной связи на телефоне |
| `--telemetry-port N` | 5300 | порт телеметрии FH6 |
| `--rate N` | 100 | частота отправки отчётов в игру, Гц |
| `--timeout N` | 500 | сколько мс ждать ввода до сброса пада |
| `--backend vigem\|console` | auto | `console` — работа без драйвера (только логи) |
| `--config PATH` | `appsettings.json` | свой файл конфигурации |
| `--verbose` | — | подробный лог |
| `--help` | — | список аргументов |

### 1.4 Настройка Forza Horizon 6

В игре: `Settings → HUD and Gameplay → Data Out → ON`, `Data Out IP` = IP вашего ПК, порт `5300`.

Это включает поток телеметрии (обороты, скорость, slip, поверхность, удары) — именно из него делаются «DualSense-ощущения».

Если FH6 запущена из **Steam** и включён Steam Input — выключите его для этой игры (ПКМ по Forza в библиотеке → «Управление вводом» → выключить), иначе Steam Input может перехватывать виртуальный пад.

## 2. Приложение на iPhone

### 2.1 Установка готовой сборки

Сборки публикуются в CI: **Actions → Build → Artifacts**.

* `PhonePad-ios-unsigned-ipa` — неподписанный IPA. Ставится через Sideloadly / AltStore /
  любой инструмент, который переподписывает приложение вашим Apple ID.
* `PhonePad-ios-signed-ipa` — подписанный IPA (появляется, если в репозитории заданы
  переменные `APPLE_SIGNING_ENABLED` и `APPLE_TEAM_ID`, а в секретах — сертификат и профиль).

> Неподписанный IPA не поставится «двойным тапом» — iOS требует подпись.
> Самый быстрый путь: скачать IPA из артефактов и переподписать через
> [Sideloadly](https://sideloadly.io) (достаточно бесплатного Apple ID) или AltStore.

### 2.2 Сборка локально

Нужен Xcode 15+ и iPhone с iOS 16+.

**Вариант A — XcodeGen (рекомендуется):**

```bash
brew install xcodegen          # macOS
cd ios
xcodegen generate
open PhonePad.xcodeproj
```

**Вариант B — вручную:** создать новый проект iOS App (SwiftUI, имя `PhonePad`), добавить все файлы из `ios/Sources/` и содержимое `ios/Resources/Info.plist` как `Info.plist` проекта.

Свою Apple ID-команду можно не ставить: в настройках проекта → Signing & Capabilities → «Automatically manage signing» снять, а в Targets → Build Settings → `CODE_SIGNING_ALLOWED = NO` — и приложение запустится на iPhone через «Personal Team» или без подписи (тогда нужен бесплатный аккаунт разработчика).

### 2.3 Использование

1. Открыть приложение → шестерёнка → ввести **IP ПК** (тот, что напечатал сервер) и порт `8888` → «Подключиться».
2. Телефон и ПК должны быть в одной Wi-Fi сети (5 ГГц лучше).
3. Раскладки: «Полная (DualSense)» — всё как на настоящем контроллере; «Гонки» — крупные педали и руль.
4. Кнопка «Гиро» включает руление по наклону телефона (центр захватывается автоматически через 0.4 с),
   а кнопка с прицелом рядом — центрирует его заново в любой момент.

### 2.4 Что где

| Файл | Назначение |
|---|---|
| `ios/Sources/PadView.swift` | мультитач-раскладка: кнопки, плавающие стики, ползунки триггеров, отрисовка |
| `ios/Sources/PadLayout.swift` | две раскладки (нормализованные координаты) |
| `ios/Sources/NetClient.swift` | UDP-канал: отправка ввода, приём обратной связи, ping/pong |
| `ios/Sources/HapticsEngine.swift` | CoreHaptics: две полосы вибрации, щелчки триггеров, клики кнопок |
| `ios/Sources/SoundEngine.swift` | синтез звуков контроллера (процедурно, без asset-файлов) |
| `ios/Sources/MotionEngine.swift` | гироскоп-руль с фильтром |
| `ios/Sources/HudView.swift` | HUD, световая полоса и панель статуса |
| `ios/Sources/WireFormat.swift` | кодирование пакетов |

## 3. Проверка без iPhone

В комплекте есть симулятор телефона — можно отлаживать сервер и тактильные эффекты до сборки приложения:

```bash
# ввод + телеметрия (имитация FH6)
python3 tools/phone_sim.py --host 127.0.0.1 --mode both --duration 10

# только телеметрия — проверка конвейера «телеметрия → вибрация/звук/HUD»
python3 tools/phone_sim.py --host 127.0.0.1 --mode telemetry --duration 10

# проверить, что сервер сбрасывает пад при обрыве связи
python3 tools/phone_sim.py --host 127.0.0.1 --mode state --duration 10 --drop-after 3

# локальная проверка кодеков протокола (сеть не нужна)
python3 tools/phone_sim.py --mode selftest
```

Самопроверка протокола, разбора телеметрии и синтеза эффектов:

```bash
dotnet run --project pc/src/PhonePad.SelfTest -c Release -f net8.0
```

## 4. Автоматическая сборка (GitHub Actions)

Workflow `.github/workflows/build.yml` выполняет на каждый пуш в `main`:

| Задача | Раннер | Что делает |
|---|---|---|
| `PC-сервер (.NET, Windows)` | `windows-latest` | сборка, самопроверка, сквозной тест «сервер + симулятор», публикация `PhonePadServer-win-x64` |
| `Симулятор телефона (Python)` | `ubuntu-latest` | `phone_sim.py --mode selftest` |
| `iOS-приложение (Xcode)` | `macos-14` | XcodeGen → компиляция → сборка под устройство → упаковка `PhonePad-ios-unsigned-ipa` |
| `iOS-приложение (подписанный IPA)` | `macos-14` | включается вручную (`workflow_dispatch`) при `vars.APPLE_SIGNING_ENABLED = true` |

Чтобы собрать подписанный IPA, добавьте в репозитории:

* secrets: `APPLE_CERTIFICATE_BASE64` (P12 в base64), `APPLE_CERTIFICATE_PASSWORD`,
  `PROVISIONING_PROFILE_BASE64`, `PROVISIONING_PROFILE_NAME`;
* variables: `APPLE_SIGNING_ENABLED = true`, `APPLE_TEAM_ID = <Team ID>`.

## 5. Устройство

```
pc/src/PhonePad.Core/     протокол, телеметрия FH6, синтез тактильных эффектов
pc/src/PhonePad.Server/   UDP-сервер, виртуальный пад (ViGEm), HUD, рассылка эффектов
pc/src/PhonePad.SelfTest/ самопроверки
tools/phone_sim.py        симулятор телефона
ios/Sources/              приложение для iPhone
docs/PROTOCOL.md          спецификация протокола (байты, смещения, маски кнопок)
```

Схема потоков данных:

1. **Телефон → ПК (8888).** Каждый кадр — полный снимок: маска кнопок, триггеры, оси стиков, гироскоп, CRC8.
2. **ПК → игра.** Снимок применяется к виртуальному Xbox-паду 100 раз в секунду.
3. **Игра → ПК.** Через виртуальный пад приходит rumble — сервер пересылает его телефону как «Body»-сообщение.
4. **FH6 → ПК (5300).** Телеметрия 324 байта: разбирается, из неё считаются ABS, пробуксовка, текстура, удары, смена передач.
5. **ПК → телефон (8889).** Вибрация (две полосы), эффекты триггеров, звуки, HUD.

## 6. Ограничения (честно)

* **iOS не может быть HID-устройством.** Нет публичного API для роли Bluetooth/USB HID — поэтому связь только по сети, а виртуальный пад создаёт ПК. (На Android это возможно: есть `BluetoothHidDevice` и USB-HID через OTG.)
* **Задержка.** Тачскрин iPhone ≈ 8–16 мс + сеть 2–10 мс → 20–40 мс против 4–8 мс у настоящего пада. В быстрых поворотах это чувствуется.
* **Адаптивный триггер** — только имитация: вибро-импульс на пороге + телеметрические эффекты. Реального сопротивления на стекле не бывает.
* **Экран закрывает обзор**, телефон скользит по столу, батарея садится (экран + Wi-Fi + вибрация).
* **Гироскоп дрейфует** — центрируйте его каждые несколько минут (кнопка с прицелом центрирует руль).
* **FH6 на ПК не поддерживает адаптивные триггеры нативно** — даже с настоящим DualSense. Именно поэтому эффекты считаются из телеметрии: так выходит точнее, чем штатная поддержка.
* **Steam Input** не умеет подключаться к сборкам Microsoft Store/Game Pass — виртуальный XInput-пад решает и эту проблему.
* **Смещения телеметрии** взяты из спецификации FH6 Data Out; если игра отдаёт другой формат,
  разбор устойчив к длине, но «незнакомые» поля будут нулевыми.
