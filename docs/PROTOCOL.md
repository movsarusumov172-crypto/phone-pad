# Протокол PhonePad (v1)

Два направления, оба по UDP.

```
Телефон (iOS)  --(input, порт 8888)-->  PC-сервер  --(feedback, порт 8889)-->  Телефон
Телефон        --(телеметрия FH6 --> ПК, порт 5300, штатный Data Out игры)-->
```

Все целые числа — little-endian. Пакеты фиксированной длины, без выравнивания.

---

## 1. Телефон → ПК: состояние ввода

Порт назначения: **8888** (UDP). Отправляется на IP ПК, заданный в настройках приложения.
Каждый пакет — полный снимок состояния (не дельты). Отправка ~100 Гц.

| Смещение | Размер | Тип | Поле |
|---------|--------|-----|------|
| 0 | 1 | u8 | `magic` = 0xF1 |
| 1 | 1 | u8 | `version` = 1 |
| 2 | 1 | u8 | `type`: 1 = State, 2 = Hello, 3 = Goodbye, 4 = Ping |
| 3 | 1 | u8 | `flags`: бит 0 — активен гироскоп |
| 4 | 2 | u16 | `buttons` — битовая маска (см. ниже) |
| 6 | 1 | u8 | `leftTrigger` (0..255) |
| 7 | 1 | u8 | `rightTrigger` (0..255) |
| 8 | 2 | i16 | `leftX` (−1000..1000) |
| 10 | 2 | i16 | `leftY` (−1000..1000) |
| 12 | 2 | i16 | `rightX` (−1000..1000) |
| 14 | 2 | i16 | `rightY` (−1000..1000) |
| 16 | 2 | i16 | `gyroPitch` (сотые градуса/с) |
| 18 | 2 | i16 | `gyroRoll` (сотые градуса/с) |
| 20 | 2 | u16 | `sequence` (счётчик, для отбрасывания старых пакетов) |
| 22 | 1 | u8 | `crc8` от байтов 0..21 (CRC-8/ATM: poly 0x07, init 0x00) |

Итого 23 байта.

### Маска кнопок (u16)

| Бит | Кнопка | XInput |
|-----|--------|--------|
| 0 | DPadUp | Up |
| 1 | DPadDown | Down |
| 2 | DPadLeft | Left |
| 3 | DPadRight | Right |
| 4 | LB | LeftShoulder |
| 5 | RB | RightShoulder |
| 6 | Back | Back |
| 7 | Start | Start |
| 8 | L3 | LeftThumb |
| 9 | R3 | RightThumb |
| 10 | PS / Guide | Guide |
| 11 | Mute | — (в Xbox 360 нет кнопки mute, игнорируется) |
| 12 | A (Cross) | A |
| 13 | B (Circle) | B |
| 14 | X (Square) | X |
| 15 | Y (Triangle) | Y |

### Счётчик `sequence`

Счётчик растёт на 1 с каждым пакетом и переполняется с 65535 на 0.
Сервер отбрасывает пакеты, чей счётчик не «новее» предыдущего (с учётом переполнения).
Пакет `Hello` обнуляет счётчик на сервере — новая сессия начинается с нуля.

### Пинг и контроль связи

* Телефон шлёт `Ping` (type = 4) каждые 2 секунды.
* Сервер отвечает сообщением `Status` с кодом 3 (`PadReady`).
* Если ответов нет дольше 6 секунд — приложение показывает «Нет ответа от ПК».
* Если ввод не приходит дольше `PhoneTimeoutMs` (по умолчанию 500 мс) — сервер
  обнуляет виртуальный пад. Без этого газ остался бы «зажатым» после обрыва связи.

## 2. ПК → Телефон: обратная связь

Порт назначения: **8889** (UDP) на телефоне. ПК шлёт на `<IP телефона>:8889`.

| Смещение | Размер | Тип | Поле |
|---------|--------|-----|------|
| 0 | 1 | u8 | `magic` = 0xF2 |
| 1 | 1 | u8 | `version` = 1 |
| 2 | 1 | u8 | `type` (см. ниже) |
| 3 | 1 | u8 | `payloadLength` |
| 4 | n | — | полезная нагрузка |

Типы сообщений и их полезная нагрузка:

| type | Сообщение | Полезная нагрузка |
|------|-----------|-------------------|
| 1 | Rumble | u8 left, u8 right, u16 durationMs (0 = удерживать до следующего сообщения) |
| 2 | Body (две полосы, «кузов») | u8 lowStrength, u8 lowFreq, u8 highStrength, u8 highFreq, u16 durationMs (0 = удерживать) |
| 3 | Trigger (адаптивный триггер) | u8 lt, u8 rt, u16 durationMs (0 = удерживать) |
| 4 | Sound | u8 soundId, u8 param |
| 5 | HUD | u16 speedKmh, u8 gear, u16 rpm, i16 lateralG×100, u8 throttle, u8 brake, u8 slip, u8 flags, u16 maxRpm |
| 6 | LED | u8 r, u8 g, u8 b |
| 7 | Status | u8 code, u8 detail |

`flags` в HUD: бит 0 — машина на трассе, бит 1 — колесо на «rumble strip».

> **HUD:** 13 байт. Поле `maxRpm` добавлено в v1.1 — приложение узнаёт красную зону
> двигателя и рисует шкалу оборотов по ней. Старые 11-байтовые пакеты тоже понимаются:
> при отсутствии `maxRpm` используется 7500 об/мин.

### Коды статуса (type = 7)

| code | Значение |
|------|----------|
| 1 | Телефон подключился |
| 2 | Телефон отключился |
| 3 | Сервер готов (ответ на Ping) |

### Световая полоса (type = 6)

iOS не умеет управлять цветом LED телефона, поэтому сервер шлёт цвет, а приложение
рисует тонкую полосу под строкой статуса: оранжевая — начало заезда, красная — ABS,
белая — столкновение.

## 3. Телеметрия FH6 (ПК ← игра)

Forza Horizon 6 шлёт пакеты **324 байта** по UDP на порт **5300** (настройка в игре:
`Settings → HUD and Gameplay → Data Out → ON`, `Data Out IP` = IP ПК, порт 5300).

Используемые смещения (float32 LE):

| Смещение | Поле |
|----------|------|
| 0 | isRaceOn (>0 — гонка идёт) |
| 8 / 12 / 16 | макс. / холостые / текущие об/мин |
| 20 / 28 | ускорение по X (боковое, м/с²) / по Z (вперёд) |
| 68..80 | ход подвески колёс FL/FR/RL/RR (м) |
| 116..128 | признак «rumble strip» по колёсам (i32) |
| 132..144 | глубина лужи по колёсам (м) |
| 148..160 | вибрация поверхности по колёсам |
| 180..192 | суммарный slip по колёсам FL/FR/RL/RR |
| 236 | изменение скорости при столкновении |
| 256 | скорость (м/с) |
| 284 | давление турбо |
| 315 | газ (0..255) |
| 316 | тормоз (0..255) |
| 318 | ручник |
| 319 | передача |
| 320 | угол руля (i8, −127..127) |

Разбор устойчив к длине пакета: если байт меньше, чем нужно конкретному полю, оно
считается нулевым (некоторые режимы Data Out отдают 232 байта вместо 324).
Пакеты короче 64 байт считаются мусором и отбрасываются.

Из этих данных PC-сервер синтезирует «кузовные» вибрации, эффекты триггеров и HUD — то же,
что делают HorizonHaptics / ForzaHaptics для настоящего DualSense, только получателем
выступает телефон.

## 4. Семантика длительности

`durationMs = 0` означает «держать, пока не придёт следующее сообщение этого типа».
Ненулевое значение — длительность одиночного импульса.
Нулевые уровни силы (`left/right`, `low/high`, `lt/rt`) выключают соответствующий канал.

Когда эффект заканчивается, сервер отправляет сообщение с нулевыми уровнями, чтобы
телефон прекратил вибрацию (иначе она продолжалась бы до следующего пакета телеметрии).
